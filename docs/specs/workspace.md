# 工作区与文件

概要：

- 工作区采用单窗口加标签页，不使用 MyGo 的 Documents API。
- 前端持有正在编辑的内容，Go 负责落盘，停止输入约 1 秒后保存。
- 工作区根是进程内可替换的状态；文件监听在每次打开文件夹后按当前根开始，后续的自定义协议在启动时注册、运行时读取当前根。
- 崩溃恢复依赖 `PathUserData` 下的未保存内容副本。
- 拖入和粘贴的图片存到 `assets/`，图片数据不经过 IPC。
- 搜索在 MVP 阶段直接扫描文件，将来改用 SQLite FTS5 的 trigram 分词。
- 文件监听通过 `Workspace.Watch` 的 Channel 交给页面，底层使用 MyGo 的 `mygo.WatchFiles`；它上报非 Markdown 文件，并过滤 Nicole 自己的写入。
- 文件树、文件操作、单文件标签页、标签页布局和设置存储都有独立的接口与路径规则。
- 启动时窗口在光标所在的屏幕居中，尺寸沿用上次保存的大小。

## 工作区接口

Go 的 `Workspace` 服务通过 `mygo.Bind` 暴露，前端经 `src/services/workspace.ts` 调用。生成客户端在 `src/services/mygo.ts`，MyGo 调用只出现在 `src/services/` 和 Go 入口（见[依赖边界](../architecture.md#依赖边界)）。

| 方法 | 行为 |
|---|---|
| `ChooseFolder()` | 打开原生文件夹对话框。取消时返回 `canceled: true`，当前工作区不变；成功时切换工作区并返回根目录、Markdown 文件列表和 `generation`。 |
| `PickFolder()` | 只打开原生文件夹对话框并返回 `path` 和 `canceled`，不切换工作区。页面确认后再调用 `OpenFolder`。 |
| `OpenFolder(path)` | 切换到用户刚选择的文件夹、Go 记录的最近文件夹或系统提供的文件的所在文件夹。其他路径返回错误，页面不能用它打开任意目录；只有系统提供文件的父目录这一授权来源会拒绝根目录、盘符根目录和主目录。目录不存在时返回固定错误 `workspace: folder does not exist`。 |
| `OpenDroppedFolder(token)` | 打开一次原生拖入授权的单个文件夹，见[拖入文件夹](#拖入文件夹)。页面只提交 token，不提交路径。 |
| `CloseWorkspace()` | 关闭当前工作区：清空根目录、递增 `generation`，并更新关闭状态，语义见[设置存储](#设置存储)。`tabs.json` 布局保留，见[没有打开的根目录](#没有打开的根目录)。 |
| `ListFiles()` | 返回当前工作区的 Markdown 文件，规则见[列文件规则](#列文件规则)。没有打开工作区时返回错误。 |
| `ReadFile(path)` | 返回 Markdown 文件原始内容的字符串，不做换行或编码转换。 |
| `WriteFile(path, content, generation)` | 原子替换文件；`generation` 与当前工作区不一致时拒绝。保证见[写入保证](#写入保证)。 |
| `ConfirmDiscard()` | 单文档界面遗留的放弃确认。多标签页界面改用页面对话框，不再调用它（见[界面与交互](ui.md#切换文件夹)）。 |
| `FinishClose(token, saved)` | 回答一次关窗请求；`token` 标识该次请求。`saved` 为 `true` 时关窗，`false` 时 Go 弹出确认框，用户明确选择放弃后才关窗。过期请求的回答会被忽略。 |
| `ListDirectory(path)` | 按需读取文件树的一层，见[文件树接口](#文件树接口)。 |
| `CreateFile(dir, name, generation)` | 在目录中新建 Markdown 文件；见[文件操作](#文件操作)。 |
| `CreateFolder(dir, name, generation)` | 在目录中新建文件夹。 |
| `RenameEntry(path, name, generation)` | 重命名文件或文件夹，返回新路径。 |
| `TrashEntry(path, generation)` | 移到废纸篓或回收站。 |
| `OpenWithDefaultApp(path, generation)` | 用系统默认应用打开文件。 |
| `RevealEntry(path, generation)` | 在 Finder、资源管理器或文件管理器中显示。 |
| `Watch(generation)` | 通过 Channel 流式返回工作区变化，见[文件监听](#文件监听)。 |
| `Search(request)` | 在**当前根目录**的磁盘 Markdown 文件中搜索，通过 Channel 流式返回匹配行和汇总，见[搜索](#搜索)。请求不包含路径，页面不能指定搜索范围。 |
| 单文件的 `SingleFileService` | 只访问用户通过对话框或系统“打开方式”明确选择的 `.md` 文件，见[单文件标签页](#单文件标签页)。 |
| `SingleFileService.RevealSingleFile(path)` | 在 Finder、资源管理器或文件管理器中显示一个仍有授权的单文件。 |
| 标签页的 `WorkspaceTabs` | 读写当前根目录记住的标签布局，见[标签页存储](#标签页存储)。 |
| 设置的 `Settings` | 读写用户数据目录中的全局设置，见[设置存储](#设置存储)。 |
| 未保存内容的 `Recovery` | 写入、列出、删除和恢复崩溃前的副本，见[崩溃恢复](#崩溃恢复)。 |

工作区根保存在进程内的一个状态对象中，`ChooseFolder()`、`OpenFolder()` 和 `OpenDroppedFolder()` 只替换这个状态并递增 `generation`。界面使用 `PickFolder()` → 页面对话框 → `OpenFolder()` 的顺序，所以取消确认时 Go 端根目录还没有变化。后续要加的自定义协议在启动时注册，运行时读取当前根，换工作区不重新注册任何东西（见[文件监听](#文件监听)与[架构](../architecture.md#进程和模块结构)）。

### 没有打开的根目录

`CloseWorkspace()` 把根目录设为空字符串并递增 `generation`；首次启动、关闭工作区和上次文件夹已不存在时都处于这个状态。依赖根目录的服务按下面处理，页面不需要先调用接口判断：

| 服务 | 无根状态 |
|---|---|
| `ListFiles`、`ReadFile`、`WriteFile` | 返回 `workspace: no folder is open`；写入不会再落到上一个根。 |
| `ListDirectory`、`CreateFile`、`CreateFolder`、`RenameEntry`、`TrashEntry`、`OpenWithDefaultApp`、`RevealEntry` | 返回同一个“没有打开工作区”错误；没有任何路径能被解析。 |
| `Watch` | 返回“没有打开工作区”，不启动 watcher；旧 watcher 在下一批事件前结束。 |
| `Search` | 返回“没有打开工作区”，不扫描磁盘。`generation` 与当前根不一致时返回“工作区已切换”。 |
| 图片协议 | 根目录为空或 `generation` 不匹配时返回 404。 |
| `Assets.PasteImage`、`Assets.ImportImages` | 返回“没有打开工作区”；drop token 不会被图片导入消耗。 |
| `WorkspaceTabs.Get`、`Save` | 返回“根目录必须是当前工作区”错误，不读写任何布局。关闭前页面先保存布局，所以 `tabs.json` 保留。 |
| `Settings.AddRecentFolder` | 返回“最近文件夹必须是当前工作区”错误。 |
| `Recovery` 的工作区副本 | 保存、删除和丢弃工作区副本都因没有根或 `generation` 不匹配而拒绝；`List` 只返回单文件副本，其他根目录只计数。 |
| `SingleFileService` | 不依赖根目录；已有的单文件授权继续有效，直到标签页关闭或应用退出。 |

关闭时 Go 会清除旧根在内存中的磁盘哈希（仍打开的单文件授权除外），并把旧根重新排到最近文件夹第一位。关闭本身不删除 `tabs.json`、恢复副本或任何用户文件。

## 列文件规则

- 递归遍历工作区，只列出普通文件；扩展名为 `.md`。扩展名比较不区分大小写。
- 不进入名字以 `.` 开头的目录，也不进入 `node_modules`；其他目录照常遍历。
- 不跟随符号链接：符号链接文件不列出，符号链接目录也不进入。
- 返回相对工作区的路径，统一用 `/` 分隔，并按字符串排序。
- 列表失败时返回错误，不返回部分结果。
- 名字以 `.` 开头的文件仍会列出，例如 `.draft.md`；只有隐藏目录被跳过。

## 文件树接口

`ListDirectory(path)` 每次只读一层，`path` 为 `.` 或相对工作区的目录路径。返回的 `FileEntry` 带 `name`、`path`（相对工作区、以 `/` 分隔）、`isDir`、`isMarkdown` 和 `size`。空文件夹返回空数组；文件树第一次展开时再读取下一层，所以打开含 `node_modules` 的工作区不需要遍历它。

- 显示文件和文件夹，包括空文件夹和非 `.md` 文件。
- 不显示 `.git`、`.DS_Store`、`Thumbs.db`、`desktop.ini`，以及名字匹配 `.nicole-<16 位十六进制>.tmp` 的本应用临时文件。
- 其他以 `.` 开头的文件和文件夹照常显示，例如 `.draft.md` 和 `.nicole/`；`node_modules` 也显示，首次展开时才读取。
- 不列出符号链接，也不进入符号链接目录；读取失败时返回错误，不返回部分结果。
- 后端按名字排序返回；界面仍按[界面与交互](ui.md#文件树)的规则用 `Intl.Collator` 排序，后端顺序只保证稳定。
- 空路径按 `.` 处理。路径经过[文件树路径守卫](#路径守卫)，不能越出工作区。

## 文件操作

| 方法 | 规则 |
|---|---|
| `CreateFile(dir, name, generation)` | 在 `dir` 中创建空文件。`name` 没有扩展名时补 `.md`；带其他扩展名时拒绝。目标已存在时返回明确错误，不覆盖。 |
| `CreateFolder(dir, name, generation)` | 在 `dir` 中创建文件夹。目标已存在时返回明确错误。 |
| `RenameEntry(path, name, generation)` | `name` 是新的名字，不含分隔符。文件或文件夹都可重命名；目标已存在时拒绝，不做替换。返回新的相对路径。 |
| `TrashEntry(path, generation)` | 文件或文件夹移到系统废纸篓或回收站；系统不支持时返回错误，不会退回永久删除。工作区根不能移走。 |
| `OpenWithDefaultApp(path, generation)` | 只接受普通文件；按[打开方式的安全规则](#打开方式的安全规则)决定直接打开、确认后打开或拒绝。 |
| `RevealEntry(path, generation)` | 文件或文件夹都可以在 Finder、资源管理器或文件管理器中显示；`path` 为 `.` 时显示工作区根。 |

- 所有操作都要求 `generation` 与当前工作区一致；切换文件夹后，旧工作区发起的操作被拒绝。
- 新名字和路径经过[文件树路径守卫](#路径守卫)：不能是绝对路径、不能含 `..`、`\` 或 `:`，也不能指向 `.git` 或本应用临时文件。
- 移动和改名在 Windows 上遇到文件被占用时重试，改名后对目录做 fsync（Windows 跳过）。
- 重命名已打开的文件后，文件监听会报告 `rename`；标签页标题和路径由界面同步，见[界面与交互](ui.md#文件树)。

### 打开方式的安全规则

文件树里的文件可能来自 clone 下来的仓库，不能因为用户点了一下就执行其中的程序。`OpenWithDefaultApp` 在调用系统默认应用之前先在 Go 端分类：

- 图片（PNG、JPEG、GIF、WebP、HEIC 等）、PDF、纯文本和常见办公文档（`.txt`、`.md`、`.csv`、`.json`、`.docx`、`.xlsx`、`.pptx`、`.odt` 等）直接打开。带执行位的文件仍要确认。SVG 因可能包含活动内容，不在直接打开列表。
- Windows 的 PATHEXT 类型（`.exe`、`.com`、`.cmd`、`.bat`、`.js` 等）及其快捷方式、注册表/安装/脚本类型（`.lnk`、`.url`、`.hta`、`.scf`、`.reg`、`.msi`、`.ps1`、`.application`、`.appref-ms`、`.settingcontent-ms`、`.msp`、`.chm`、`.jnlp`、`.ws`），macOS 的 `.command`、`.tool`、`.terminal`、`.jar`、`.pkg`、`.scpt` 等，以及 Linux 的 `.desktop` 直接拒绝，不弹确认框。
- 其他类型，或 Unix 上带执行权限（`0o111`）的文件，由 Go 弹出原生确认框，写明文件名并说明“打开后可能会运行程序”。只有用户选择“打开”才调用默认应用；页面不能伪造这个确认框。用户取消时不打开，也不返回错误；启动器类型被拒绝时返回错误。
- “在 Finder/资源管理器中显示”不经过这条限制，仍然只受文件树路径守卫约束。

## 路径守卫

`ReadFile` 和 `WriteFile` 的路径参数都是相对工作区的路径，而且只能指向符合[列文件规则](#列文件规则)的 Markdown 文件：扩展名 `.md`、不在隐藏目录或 `node_modules` 里、最终是普通文件。图片写入由 `Assets` 单独提供，不放开这两个方法。

文件树和文件操作使用更宽的文件树路径守卫：允许非 `.md` 文件、隐藏目录（`.git` 除外）和 `node_modules`，因为它们在[文件树](ui.md#文件树)里可见；移动、删除和用默认应用打开都需要这一范围。文件树守卫不放开 `ReadFile` 和 `WriteFile` 的 Markdown 限制，也不允许操作 `.git`、系统文件或本应用临时文件。所有守卫都先用 `os.Root` 操作，再用 `filepath.EvalSymlinks` 确认目标仍在工作区内；文件树不列出符号链接，操作也拒绝最终目标是符号链接的路径。

- 空路径、`.`，或包含 `\` 或 `:`；无论当前平台是什么，`..\` 都按非法路径处理。
- 绝对路径，包括 `/...`、`C:\...` 和 `C:/...`；以盘符开头的路径在所有平台上都拒绝。
- 含 `.`、`..` 或空分段的路径；校验同时使用 `fs.ValidPath` 和 `filepath.IsLocal`。
- 解析符号链接（`filepath.EvalSymlinks`）后不在工作区内的路径。读取检查目标文件本身；写入检查目标文件，或新文件的父目录。
- 符号链接指向工作区外、隐藏目录或 `node_modules` 时读写都拒绝；指向工作区内可见 Markdown 文件时允许，写入落到链接目标。
- 悬空符号链接不会写入，也不会被替换成普通文件。

实际的文件打开、读取、创建、改名、删除和 chmod 都通过 `os.OpenRoot` / `os.Root` 完成，保证操作不越出工作区根；`filepath.EvalSymlinks` 只用于在操作前确定并检查目标。仍有两个限制：检查和实际打开之间路径组件可能被替换，从而绕过隐藏目录或 `node_modules` 规则；工作区根目录本身被替换时，后续操作会落到新目录上。

工作区根在打开时解析符号链接并保存为绝对路径。包含判断按路径分段（`filepath.Rel`）而不是字符串前缀，因此 `notes-other` 不会被当成 `notes` 的子目录。大小写不敏感的文件系统上，父目录路径必须使用磁盘上的实际大小写；不同大小写的路径按工作区外处理（fail closed）。前端只使用 `ListFiles()` 返回的路径，因此不受影响。

## 写入保证

- 读写都按字节处理：换行符、文件末尾是否有换行、UTF-8 BOM 都原样保留。
- CodeMirror 内部把换行统一成 `\n`；前端在加载文件时统计换行风格（LF、CRLF 或 CR），保存时按同一风格写回，所以使用一致换行风格的文件不会被整篇改写。
- 同一文件混用多种换行时，前端标记为“换行风格混合”，不自动保存，并保留待保存内容；状态栏和横幅的显示见[界面与交互](ui.md#保存状态)。切换标签页不丢失内容，也不需要确认；关闭标签页、切换文件夹或关窗时，用户必须在页面对话框中选择放弃更改；取消则保留当前编辑。文本撤销回读入时的内容后，待保存内容会被清空，不再阻止关闭。
- 写入先在目标文件所在目录创建临时文件，写完、同步并关闭后再改名替换目标。
- 失败时目标文件保持原内容，临时文件被删除。
- 新文件使用 `0666` 并遵循进程 umask；已有文件保留权限位。目标文件没有写权限时拒绝保存，并返回明确错误。
- 改名在 Windows 上遇到文件被占用会重试；改名后对所在目录做 fsync（Windows 跳过）。
- 打开工作区时清理本应用遗留的临时文件，只删除名字匹配 `.nicole-<16 位十六进制>.tmp` 且修改时间早于 10 分钟的文件；最近的文件可能属于另一个仍在写入的实例，不删除。
- 保存失败会返回错误；前端只显示“保存失败”，不自动重试。

## 单文件标签页

工作区之外的单个 `.md` 文件由 `SingleFileService` 读写。授权按文件进行，不代表所在文件夹：

- `ChooseSingleFile()` 打开只显示 `.md` 的原生文件对话框；用户选中的文件直接授权。
- 系统“打开方式”或双击把文件交给 `App.OnOpenFile`；Go 把它记为“已提供”，但**不自动授权**。页面显示确认后调用 `AcceptSingleFile(path)`，只有与已提供路径一致的请求才会授权。
- “打开所在文件夹”是一次性授权：`OpenFolder` 成功后 Go 删除该文件对应的已提供项；用户取消、对话框被关闭或打开失败时，页面调用 `DismissOfferedFile(path)` 删除它。位于主目录、文件系统根目录或盘符根目录的文件不显示这个选项；当授权来源只是该文件时，Go 的 `OpenFolder` 也拒绝这些根目录。用户主动选择、当前根目录和最近列表不受这条限制。
- 授权保存解析符号链接后的绝对路径；`ReadSingleFile(path)` 和 `WriteSingleFile(path, content)` 只接受完全相同的路径。同一目录下的其他文件、相对路径、目录和非 `.md` 文件都拒绝。
- 授权只存在内存中；关闭标签页时调用 `ReleaseSingleFile(path)`，重启应用后需要重新选择或确认。单文件标签页不属于任何根目录：切换文件夹时保留，不计入“会关闭”的标签页数量，不写入标签页布局。唯一的例外是[崩溃恢复](#崩溃恢复)：用户从副本列表中选择恢复时，Go 重新核对路径后按解析后的绝对路径授权一次；页面没有按任意路径授权的入口。
- 写入复用[写入保证](#写入保证)的原子替换：先写同目录临时文件，再改名；保留权限位，只读文件拒绝写入，失败时旧内容不变。文件已被外部删除时，再次保存会在原路径重新创建，与工作区文件的行为一致。换行风格的检测和“换行风格混合”保护仍由前端负责。
- 单文件不属于工作区文件树，不在 `Watch` 范围内；界面按[界面与交互](ui.md#打开工作区之外的文件)显示完整路径、横幅和独立标签页。外部修改/删除不会自动发现，保存失败等状态仍由前端按普通文件处理。
- 打开单文件总是在活动标签页右侧新开标签页；同一路径同时最多一个标签页，已在标签页中时切换到该标签页。关闭某个单文件的标签页时释放该文件的授权。

安全模型见[架构](../architecture.md#安全)。

## 设置存储

全局设置保存在 `PathUserData/settings.json`。可用 `NICOLE_USER_DATA_DIR` 覆盖用户数据目录（见[开发](../development.md#数据隔离)）。`Settings` 服务的读写接口：

| 方法 | 内容 |
|---|---|
| `Get()` | 返回全部设置；文件不存在时返回默认值，不创建文件。 |
| `MigrateLegacyTheme(legacy)` | 旧版存在 `localStorage` 的 `nicole-theme` 迁移到设置；文件已经有 `theme` 字段时不覆盖。调用方成功后删除旧值。 |
| `SetTheme(theme)` | 保存 `system`、`light` 或 `dark`，并调用 `mygo.Theme.SetSource`，让原生菜单和对话框跟随。 |
| `SetEditorMode(mode)` | 保存全局编辑模式 `live`、`immersive` 或 `source`；非法值返回错误且不改写文件。 |
| `SetSidebarWidth(width)` | 保存侧栏宽度，限制在 200–400px。 |
| `SetExpandedFolders(root, folders)` | 按根目录保存文件树展开状态；`folders` 是相对路径，只存显示状态，不用于访问文件。 |
| `AddRecentFolder(folder)` / `RemoveRecentFolder(folder)` | `AddRecentFolder` 只接受当前已打开的根目录，页面不能用它授权另一个目录；`Workspace.open` 成功后由 Go 写入最近列表，页面只更新本地显示。`RemoveRecentFolder` 只移除记录。 |

`settings.json` 的字段为 `theme`、`editorMode`、`sidebarWidth`、`recentFolders`、`expandedFolders`（根目录绝对路径 → 展开的相对路径数组）和 `workspaceClosed`。默认主题是 `system`，默认编辑模式是 `live`（实时预览），默认宽度 252px，最近文件夹和展开状态为空，`workspaceClosed` 缺省为 `false`；`editorMode` 缺失或非法时按 `live` 读取。`workspaceClosed` 由 `Workspace.CloseWorkspace()` 写成 `true`，由任何一次成功打开文件夹（`ChooseFolder`、`OpenFolder`、`OpenDroppedFolder`）清除；页面只在启动时读取它来决定是否恢复上次的文件夹，没有单独写入它的接口。写入在目标目录创建临时文件后改名替换，一次只写一个完整文件；损坏的设置文件不会被部分覆盖。

文件已存在但不是合法 JSON 时，读取会先把原文件重命名为 `settings.json.corrupt-<UTC 时间>`，再以默认值继续，后续设置可以正常保存；原文件保留下来供排查。备份重命名失败时返回错误，不覆盖损坏文件。启动时的主题读取也遵循这个行为，失败时保持系统外观。

主题从 `localStorage` 迁移后，系统的外观变化由页面监听 `prefers-color-scheme`；`system` 时原生外观也由 `Theme.SetSource(ThemeSystem)` 跟随系统。详见[主题与字体](theming.md#当前实现)。

## 标签页存储

`WorkspaceTabs` 把每个根目录的标签页布局保存在 `PathUserData/tabs.json`：

| 方法 | 内容 |
|---|---|
| `Get(root)` | 返回这个根目录记住的标签页、活动标签页和最近文件；没有记录时返回空布局，不创建文件。 |
| `Save(root, tabs, active, recentFiles)` | 替换这个根目录的记录；标签和最近文件都为空时删除记录。 |

`Get` 和 `Save` 只接受当前已经打开的根目录，页面不能用这个服务读写其他目录的记录；没有打开的根目录时两者都拒绝。布局中的路径相对根目录、以 `/` 分隔，只用于显示和重新打开文件；它不是文件访问授权，Go 端用与文件树相同的规则拒绝绝对路径、`..`、`\`、`:`、`.` 和非法分段。单文件标签页不写入布局或最近文件。关闭工作区前页面先保存当前布局，所以关闭后布局仍在，下次打开这个根目录时恢复。

每条记录包含标签类型（`markdown` 或 `preview`）、相对路径、占位页文件大小，以及 Markdown 标签的选区、顶部行号和行内像素偏移。`recentFiles` 是这个根目录最近激活的 `.md` 相对路径，最新在前、去重、最多 20 条；标签页切换时更新，随现有的标签页写入节流保存。它只用于[命令面板](ui.md#命令面板)文件模式的排序，不是文件列表缓存，也不是访问授权。撤销历史只在内存中保留，不写入这里，所以切换文件夹再切回和重启都只恢复文本、选区和滚动位置。单次保存最多保留 200 个标签；选区有大小上限，超出时丢弃选区而不是整个布局。JSON 语法无效的选区会被丢弃。

`tabs.json` 与 `settings.json` 一样原子替换；文件损坏时先改名为 `tabs.json.corrupt-<UTC 时间>`，再以空布局继续。读取或备份失败不会阻止编辑，标签页记忆是尽力而为。启动和切换文件夹时，恢复前会重新读取文件或目录项，已不存在的标签跳过。

## 窗口位置

- 启动时窗口在光标所在的显示器工作区居中，而不是恢复上次的位置。
- 尺寸沿用上次保存的尺寸；没有保存过时使用默认 `1100×780`。
- 尺寸超过当前显示器工作区时缩小到工作区大小。
- 状态仍保存在 `PathUserData/window-state.json` 的 `main` 下，格式与 MyGo 的默认存储一致；移动、缩放、最大化和关闭时的记录仍由 MyGo 完成。
- 实现使用 `Screen.CursorScreenPoint`、`Screen.DisplayNearestPoint` 和自定义 `WindowStateStore`；拿不到显示器信息时回退到 `Screen.PrimaryDisplay`。

## 工作区模式

只用一个窗口，用标签页切换文档。

**不用** MyGo 的 Documents API（见 [MyGo 参考](../references/mygo.md#documents-api)）：每多一个窗口就多一个 WebKit 页面进程，约多 40–50MB。内存预算见[性能](performance.md#预算)。

使用 MyGo 的文件关联接收系统打开的 `.md` 文件；最近文件夹由 Go 在 `Workspace.open` 成功后写入[设置存储](#设置存储)，页面只维护当前会话的本地显示。打开一个 `.md` 文件时，按它是否位于已打开或最近用过的文件夹中分别处理，规则见[界面与交互](ui.md#打开工作区之外的文件)。

启动时页面按[设置存储](#设置存储)中的关闭状态决定是否恢复最近文件夹的第一项；系统“打开方式”传入的文件按上面的规则单独处理。关闭工作区只关闭根目录本身，不关闭窗口。

界面按“单窗口多根目录”设计：P0 只有一个根目录，打开另一个文件夹时替换当前根目录；P1 允许同时添加多个根目录，仍在同一个窗口里，不增加 WebKit 进程（见[界面与交互](ui.md#根目录)）。

## 保存

- **前端管正在编辑的内容，Go 管磁盘。**
- 停止输入约 1 秒后，把全文发给 Go 保存。文章很小，不需要增量同步。
- Go 先写临时文件，再改名覆盖目标文件，避免中途失败留下半个文件；保证见[写入保证](#写入保证)。
- 自动保存在三种编辑模式下都生效（见[编辑模式](editor-modes.md#所有模式共用的能力)）。
- 每个标签页有独立的文档模型：文本、磁盘基线、换行风格、保存状态、外部状态和生成号都按路径保存；编辑器只是活动标签页的视图。切换标签页只换视图，不保存、不确认，也不销毁模型。
- 自动保存和手动保存始终使用模型自己的 `path`、`generation` 和文本，而不是活动标签页的。写入开始后模型即使被改名或切到后台，完成时也只更新与该路径匹配的模型；路径已变化时不把旧路径的结果当成新基线，避免旧保存写进别的文件。
- 关闭需要处理状态的标签页时，前端先用页面对话框确认并列出文件；普通编辑中的标签页会先尝试保存。批量关闭（关闭其他、关闭右侧、关闭全部）逐个保存后统一确认，取消时一个都不关闭。
- 切换文件夹时先调用 `PickFolder`，用户选择后按[界面与交互](ui.md#切换文件夹)完成保存、确认、恢复副本等待和失败回滚，再调用 `OpenFolder`。文件夹对话框期间的编辑会被保存，取消原生对话框不会丢弃内容。单文件标签页不参与这次保存和关闭，切换后保留。
- 关闭工作区的页面流程见[界面与交互](ui.md#关闭工作区)。Go 侧由 `CloseWorkspace` 清空根目录、递增 `generation` 并更新关闭状态；`tabs.json` 和恢复副本的保留规则见[没有打开的根目录](#没有打开的根目录)与[崩溃恢复](#崩溃恢复)。
- 工作区读取开始时记录根目录和 `generation`；异步结果返回时两者任一已变化，就丢弃这次读取，不插入标签页、不显示错误，也不把旧根目录的相对路径交给新根目录。新开、重开、启动恢复和工作区内的占位页读取都遵循这条规则。单文件读取没有根目录代际，但结果返回时也会再次确认该路径是否已有标签页。
- 工作区标签保存请求带打开时的 `generation`。切换期间的旧写入会被 Go 拒绝，不会落到新工作区。
- 关窗时 Go 先阻止关闭，通过携带 `token` 的 `workspace:save-before-close` 事件让前端保存全部标签页和当前根目录的标签布局。全部保存成功后前端调用 `FinishClose(token, true)` 关闭窗口；保存失败或混合换行时调用 `FinishClose(token, false)`，由 Go 弹出“仍然关闭 / 取消”确认框，只有用户明确选择仍然关闭才销毁窗口。重复关窗沿用第一次请求；页面无响应时最多等待 5 秒后关窗，超时之后到达的回答因 token 过期而无效。前端还在 `beforeunload`、`pagehide` 和页面隐藏时尝试立即保存，这段时间内的极端情况仍需崩溃恢复兜底。页面隐藏、`pagehide`、`beforeunload` 和 `workspace:save-before-close` 到达时，先写崩溃恢复副本，再保存；写副本和保存互不等待。需要副本的模型包括有未保存内容的模型，以及内容还在标签页但文件已被外部删除的模型。关窗路径在调用 `FinishClose` 前最多再等 1 秒，让副本写入和删除完成，且总等待仍不超过 Go 的 5 秒上限。

### 输入法组合期间

自动保存只写已经上屏的文字。组合状态直接取 CodeMirror 视图的 `compositionStarted` / `composing`，另有一个只影响自动保存的“组合已失效”标记；只有活动标签有编辑器视图，不另存一份组合状态：

| 情况 | 行为 |
|---|---|
| 输入法组合期间 | 不触发自动保存，磁盘上不出现拼音半成品 |
| 组合结束（上屏或取消） | 重新计时，约 1 秒后保存；内容变回原样就不保存。保存失败、混合换行等暂停状态见下方说明 |
| 组合期间退出或关闭窗口 | 按现有流程保存，宁可写入拼音，也不丢内容 |
| 组合期间写恢复副本 | 保持现状，可以包含拼音，因为副本不是用户的文件，只用来防丢 |

- 判断不只在计时器到点时进行：自动保存排队等待或同一次保存写完一轮后准备再写时，都会在真正写盘前重新判断；排队或写入期间开始的组合同样不写盘。被挡下时保持未保存状态并重新计时。
- 计时器在组合开始前已经运行时，到点同样不写盘；`compositionend` 到达后重新开始 1 秒计时。
- 只有活动标签的视图能处于组合状态，其他标签的自动保存照常到点写入。
- 组合结束没有事件时（视图被销毁、窗口或编辑器失焦、WebKit 漏发 `compositionend`）：保存被挡下时按 1 秒复查；活动视图被销毁或编辑器失焦后，复查会照常保存当前文本。
- 按键兜底：按键监听在窗口上；收到 `isComposing` 为 false 且 `keyCode` 不是 229 的按键（单独的修饰键不算）时，把当前标签的这次组合视为已结束，自动保存不再等它。下一次 `compositionstart` 或 `compositionend` 会清除这个标记。这个信号只用于自动保存，不修改 CodeMirror 状态，也不影响渲染。
- 2026-11-08 的事件顺序探测使用裸 `contenteditable` + WKWebView；之后在完整应用里用鼠须管复测：组合中停顿、切换候选、部分选词、⌘S、Home、End 都不写拼音；上屏约 1 秒后保存；Esc 不写盘；组合中按 ⌘Q 不退出，从菜单退出会写入拼音。事件顺序为：组合中的 keydown（字母、方向键、Tab、⌘S、⌘Z、F5、Home/End 等）都是 `keyCode=229` 且 `isComposing=true`；上屏或取消时 `compositionend` 先触发，随后同一按键的 keydown 是 `keyCode=229`、`isComposing=false`；窗口失焦时先 `window blur`，随后 `compositionend` 提交未上屏文字。实测没有观察到 `compositionend` 丢失，所以按键兜底在实测序列上不会触发。其他输入法没有实测。
- 剩余局限：组合没有结束事件、视图未销毁也未失焦，且之后没有符合上述条件的按键时，自动保存不会恢复；恢复副本继续按原节奏写入，内容不会丢。CodeMirror 对 Safari dead-key 组合的内部收尾只调用自己的处理函数，不派发 DOM `compositionend`，所以 `onCompositionEnd` 不会被调用；这种情况靠下一次 1 秒复查恢复，等待时间为 0 到 1 秒。
- 关闭标签、切换文件夹、关窗和页面隐藏走显式保存，不受组合状态限制；⌘S 等全局按键在组合期间仍按现有规则提前返回。
- 保存失败、换行风格混合、外部修改或删除造成的暂停保持原样。一次没有文档变化的组合结束只重新处理已有被挡计时器或已回到原样的文本，不会重试保存失败的标签；新输入仍会触发下一次自动保存。

## 崩溃恢复

Go 在 `PathUserData/recovery/` 保存未保存内容的副本；界面流程见[界面与交互](ui.md#崩溃恢复)。前端在模型变脏（`text !== originalText`）的那一刻开始计时：2 秒后写第一份，之后每 5 秒检查一次，文本或 `baselineUnconfirmed` 相对上一份副本有变化才写。计时不随按键重置，与自动保存的 1 秒计时互不影响。每个模型一个计时器。

立即写副本的情况：保存失败、换行风格混合、因外部修改或删除暂停自动保存、强制保存被叫停进入 `paused`。页面隐藏、`pagehide`、`beforeunload` 和 `workspace:save-before-close` 到达时，先对所有需要副本的模型写副本，再保存；两者都 fire-and-forget，不互相等待。

删除副本的情况：保存成功且 `text === originalText`；文本撤销回基线；用户在关闭、切换等任何对话框中选择放弃更改；“载入磁盘版本”或“使用磁盘版本”；关闭标签页；单文件的 `ReleaseSingleFile`。保存成功但保存期间又有新输入时不删。用户在关窗确认中选择“仍然关闭”时不删，下次启动继续提示。文件或文件夹改名、移动后，旧路径的副本随标签路径变化删除，并立即按新路径写一份；新路径没有哈希记录时按未确认基线处理。副本写入失败只记日志，不增加界面提示；非 Markdown 的占位页标签不写副本。

### 目录与格式

- 文件名是 `sha256(kind + "\0" + root + "\0" + path)` 的前 16 位十六进制加 `.json`。`kind` 为 `workspace` 或 `single`；工作区副本的 `root` 是根目录绝对路径，单文件副本的 `root` 为空。读取时校验文件名与内容推导的 id 一致，不一致按损坏处理。副本不随 generation 失效，按根目录绝对路径加相对路径（单文件按绝对路径）键控。
- 字段：`version`、`kind`、`root`、`path`、`savedAt`、`diskHash`、`lineEnding`、`text`。`savedAt` 是 Go 写入时的 RFC 3339 时间；`text` 统一为 `\n` 换行；`path` 在工作区中是相对路径、以 `/` 分隔，在单文件中是解析符号链接后的绝对路径。
- `diskHash` 是“Nicole 最后一次读或写该文件时内容的 SHA-256”。`ReadFile`、`WriteFile`、`ReadSingleFile`、`WriteSingleFile` 成功时由 Go 按绝对路径记在内存，只记哈希，不缓存内容；写副本时取这条记录，不重新读磁盘。没有记录时留空，恢复时按已更改处理（fail closed）。同一路径已有副本时，新副本在没有内存记录的情况下沿用旧副本的 `diskHash`，避免重复写副本把已知的磁盘基线降级为未知。
- 页面在副本请求里标记 `baselineUnconfirmed`：标签处于外部修改/删除状态，或恢复内容尚未被用户接受时为真。此时 Go 置空 `diskHash`，也不从旧副本回填。只有用户确认过磁盘基线后（例如自动载入磁盘内容、“保留我的版本”或“载入磁盘版本”成功），副本的基线才会前进，避免第二次崩溃把未确认的磁盘内容判成 `same` 后自动覆盖。
- 切换根目录时清掉旧根的记录，但仍打开的单文件标签的哈希保留；列表读取、恢复检查和 `RestoreSingleFile` 对父目录变成符号链接等情况使用同一套拒绝规则。
- 每次写入替换该路径的旧副本；复用 `settings.json` 和 `tabs.json` 的原子替换模式。JSON 用不转义 HTML 字符的编码器写入，避免普通 Markdown 膨胀。无法解析或字段不合法的文件改名为 `<名>.corrupt-<UTC 时间>` 后跳过，其余副本继续列出；损坏备份按文件名中的 UTC 时间戳（无法解析时按 mtime）排序，只保留最近 20 个，且只清理 `.corrupt-*` 文件。
- 单个副本的 JSON 文件最多 8MB；写入端先序列化再按 JSON 字节数检查，读取端使用同一上限。`recovery/` 总量最多 64MB，统计时不计 `.corrupt-*` 备份。超过上限时拒绝新副本，不淘汰其他文件的副本；替换同一路径时旧文件不计入上限。
- 工作区副本的 `Save`、`Delete`、`Discard` 和 `List` 必须带 `generation` 且与当前根一致，规则与 `WriteFile` 相同。单文件副本不受 generation 限制，但写入时必须通过 `grantedPath` 核对当前授权。

### 磁盘状态与恢复

`List` 由 Go 读取磁盘并返回每条副本的 `diskState`：

| `diskState` | 判定 | 全部恢复时 |
|---|---|---|
| `same` | 当前内容哈希与 `diskHash` 相同 | 副本作为待保存内容载入标签页，由自动保存写回，成功后删除副本 |
| `changed` | 哈希不同，或没有 `diskHash` | 副本为 `text`，磁盘内容为 `originalText`，`externalState = modified`，不自动保存，显示外部修改横幅 |
| `missing` | 文件不存在 | 副本为 `text`，`externalState = deleted`，显示删除横幅；重新保存在原路径重建文件 |

`List` 同时返回 `text` 和 `diskText`（缺失时为空），供页面计算字数差；`changed` 时页面用 `diskText` 作为 `originalText`。页面不自行读取磁盘，只比较 Go 返回的 `diskText`。`List` 的结果是打开对话框时的快照；用户点击“全部恢复”“逐个查看”或“保留恢复内容”时，页面重新调用 `List`，以最新的 `diskState` 和 `diskText` 为准。保留恢复内容时不能只看 `diskState`：副本可能因审阅期间编辑重写而丢失 `diskHash`；等待 `List` 期间标签的 revision 或外部状态变化时放弃强制保存；不可恢复的副本不写盘，`missing` 转删除，否则只有 `diskText` 与标签 `originalText` 相同时才强制保存，不同就转外部修改。对话框打开期间磁盘再次变化时，不自动写回，转为外部修改或删除状态；已有标签的基线比快照新时，不用旧 `diskText` 覆盖它。

### 单文件副本

工作区外的单文件也写副本，并受三条约束：

1. Go 在写单文件副本时核对路径当前已授权（`grantedPath`），否则拒绝；`recovery/` 中只可能出现曾被授权的路径。
2. 副本保存解析符号链接后的绝对路径。恢复时 Go 再检查路径：文件不存在时仍允许授权，以便在原路径重建（与 `WriteSingleFile` 一致）；指向目录、非 `.md`、已成为符号链接，或文件缺失但父目录已变成符号链接、路径已改变时拒绝。列表的“无法恢复”标注与 `RestoreSingleFile` 共用这套路径检查；列表还会读取内容，读盘失败时同样标为“无法恢复”。
3. 重新授权只能通过“恢复某条副本”触发；同一进程内一条副本只能恢复一次，副本随恢复后的保存、放弃或丢弃删除。页面没有按路径授权的入口。

这条例外让单文件授权可以经恢复副本跨重启延续一次；代价和安全边界见[架构](../architecture.md#安全)。

### 其他根目录

启动时只列出最后打开的根目录和单文件的副本。其他根目录的副本只返回数量，不读取内容；列表底部说明“另外 N 个文件夹还有未保存的内容，打开它们时会提示”。`OpenFolder` 成功并恢复 `tabs.json` 布局后，如果该根有副本，再次显示同一个对话框。关闭工作区或没有打开根目录时，`List` 只返回单文件副本，所有工作区副本都只计入“其他文件夹”；`generation` 在无根状态下不参与列表判断，单文件副本仍可恢复。最近文件夹已不存在而进入“开始写作”时同样如此。“全部丢弃”只删除对话框里列出的副本。

## 图片

| 来源 | 做法 |
|---|---|
| 拖入文件 | 编辑器拦截编辑区里的文件拖放；窗口的 `Window.OnFileDrop` 把路径保存在 Go，并向页面发一次性 token 和落点坐标。页面先用 `EditorHandle.containsPoint` 确认落点在编辑区内，再用坐标创建插入位置，`Assets.ImportImages(docPath, generation, dropToken)` 按 token 取路径并复制图片。token 约 10 秒过期，只能使用一次。 |
| 粘贴 | 编辑器检测到剪贴板里有图片时阻止默认粘贴；`Assets.PasteImage` 由 Go 先读剪贴板里的本地文件列表。列表非空时只导入其中的图片文件，没有图片就返回“剪贴板没有图片”，不再回退读位图，避免把文件图标当图片插入；列表为空时才读取 PNG 位图。 |

保存：

- 图片存到**工作区根目录**的 `assets/`，不是当前文件旁边的目录。目录不存在时自动创建；`assets` 是符号链接或普通文件时拒绝写入。已有目录的权限不变，新文件使用 `0666` 并受 umask 约束。
- 文件名：
  - 粘贴位图：`image-YYYYMMDD-HHMMSS.png`，时间为本地时间。
  - 拖入或粘贴文件：原文件名去掉扩展名，保留 Unicode；空格和 `/`、`\`、`:`、`*`、`?`、`"`、`<`、`>`、`|` 换成 `-`，首尾的 `.`、空格和 `-` 去掉，最多 60 个字符。扩展名统一小写。
  - 重名时在扩展名前依次加 `-2`、`-3`，直到找到未占用的名字。
- 插入相对当前文件的 Markdown 图片语法，替代文本为空，例如 `![](../assets/image-20261031-153000.png)`；路径按段做 URL 转义。相对路径以调用方传入的 `docPath` 为基准，即使该文档是工作区内的符号链接也不改用链接目标的目录。非空行开头单独占一行（包括普通行；三种模式一致）。沉浸模式块第一行的上方插入规则见[编辑器模式](editor-modes.md#行首边界与-enterbackspace)；块续行、实时预览和源码模式保持基线，其他位置直接插在光标处；空块在标记后的内容位置插入。一次粘贴或一次拖入（可含多张）在编辑器中是一个撤销步。
- 剪贴板位图只接受 PNG；macOS 的 TIFF 等格式由 MyGo 转成 PNG。粘贴和拖入都先按扩展名筛选，再检查字节确实是图片；SVG 去掉开头的 BOM、XML 声明、注释和 DOCTYPE 后，第一个元素必须是 `<svg`。没有图片扩展名的文件直接忽略，不插入链接。源文件是符号链接或非常规文件时拒绝，不跟随链接读取。
- 一次拖入多张图片时，先读完并校验全部文件，全部通过后才开始写入；写入失败时删除本次已经写入的文件并返回错误，不留下半批图片。粘贴文件列表出现同类错误时同样不写任何文件。
- 写入先在同一目录创建临时文件，再用**不覆盖已有文件**的硬链接发布到目标名；目标已存在时换下一个后缀，绝不替换已有图片。失败时目标文件不存在，临时文件被删除，权限规则与[写入保证](#写入保证)相同。文件系统不支持硬链接时（例如 exFAT/FAT、部分 SMB/NFS 挂载），改用 `O_EXCL` 直接创建目标文件并写入；这仍不会覆盖已有文件，但目标名从写入开始就可见，读者可能看到尚未写完的内容，因此没有“先写临时文件再发布”的原子性，写入失败时会删除该目标文件。
- 图片数据不经过 IPC：Go 只返回保存后的相对路径和 Markdown；页面只传文档路径、generation 和 drop token。
- 没有打开工作区时，粘贴和拖入图片都返回“没有打开工作区”，不创建 `assets/`。
- 中文输入法组合期间收到插入请求时先排队，组合结束后再插入；编辑器用插入凭据（ticket）持续映射位置，因此不会打断候选框，也不会因等待期间的编辑而落到错误位置。
- 手测项：在 Finder 里复制一张 jpg 后按 ⌘V，应导入原文件并插入相对路径，而不是粘贴图标或位图；从 Finder 把图片拖进编辑区，应保存到 `assets/` 并在落点插入。真实剪贴板和拖放不进入自动化测试。

显示：

- 编辑器把图片 URL 交给 `resolveImage`。相对路径按当前文件所在目录解析，开头的 `/` 表示工作区根；结果转换成 `nicole-image://localhost/<generation>/<工作区相对路径>`。
- `http`、`https` 和 `data:image/*` 原样保留。其他绝对 URL、协议相对 URL（`//`）、越出工作区、隐藏目录、`node_modules`、不支持的扩展名，以及含 `?` 或 `#` 的本地路径都返回 null，编辑器保留 Markdown 原文。
- 协议只提供当前工作区里的图片，扩展名清单为 `.png`、`.jpg`、`.jpeg`、`.gif`、`.webp`、`.svg`，比较不区分大小写。路径经与[路径守卫](#路径守卫)相同的检查和 `os.Root` 打开；越界、隐藏目录、`node_modules`、符号链接逃逸、非图片扩展名和旧 generation 都返回 404。响应带正确的 `Content-Type`；安全约束见[架构](../architecture.md#安全)。

## 拖入文件夹

开始写作页把文件夹拖进窗口时，文件路径同样只从 `Window.OnFileDrop` 进入 Go。原来的 `assets:file-drop` 事件增加一个可选的文件夹 token，页面不接触路径：

- `Window.OnFileDrop` 收到恰好一个路径，且 `Lstat` 确认它是真实目录（不是文件、符号链接或不存在路径）时，Go 保存该路径并生成一次性文件夹 token；同一事件里图片 side 的 token 规则不变。
- 文件夹 token 与图片 drop token 一样约 10 秒过期，第一次调用 `Workspace.OpenDroppedFolder(token)` 时取出并删除；即使随后解析或打开失败也已消耗。过期或未知 token 返回错误。
- `OpenDroppedFolder` 只使用 drop 时保存的路径，不接收页面传入的路径。它复用 `OpenFolder`/`open` 的根目录解析、目录检查和代际递增，成功后按[设置存储](#设置存储)更新最近文件夹和关闭状态，因此与原生文件夹对话框打开同一个目录的效果一致。
- 多个路径、普通文件、不存在的路径或符号链接不生成文件夹 token，页面在开始写作页显示“只能拖入一个文件夹”。有工作区或标签页打开时页面忽略文件夹 token；Go 侧 token 到期自然失效。
- 文件系统或 `Lstat` 检查与真正打开之间存在路径可能被替换的时间窗，沿用[路径守卫](#路径守卫)的同一限制；token 只把授权范围限定为 drop 时的那一个目录，不把任意路径交给页面。

## 搜索

MVP 阶段由 Go 直接扫描当前工作区的磁盘文件，通过 Channel 流式返回结果；文件多了以后再上 SQLite FTS5，使用 **trigram 分词**，默认分词器切不开中文。界面行为见[全文搜索](ui.md#全文搜索)。

### 请求与范围

`Search(request, parts)` 只搜索当前根目录，`request` 的字段为：

| 字段 | 含义 |
|---|---|
| `generation` | 打开工作区时返回的代际；与当前根不一致时拒绝，不扫描任何文件。 |
| `query` | 查询文字；为空时返回错误。字面搜索直接查找这段文字，正则搜索按 RE2 解释。 |
| `caseSensitive` | 为 `false` 时不区分大小写；字面搜索和正则搜索都使用 Unicode 简单大小写折叠。 |
| `regex` | 为 `false` 时把查询当作字面文字；为 `true` 时使用 Go 标准库的 RE2，不支持回溯引用和环视。非法表达式返回“正则表达式无效”类错误，不会开始流式输出。 |

- 扫描范围与[列文件规则](#列文件规则)共用同一套事实：普通 `.md` 文件，扩展名比较不区分大小写；不进入名字以 `.` 开头的目录和 `node_modules`；不跟随符号链接文件或目录。`.draft.md` 这类隐藏文件仍会被搜索。
- 走查和读取都通过当前工作区的 `os.Root`，请求里没有绝对路径或根目录字段。页面不能借搜索访问工作区之外的目录，也不能把单文件标签的授权当成目录授权。
- 搜索以磁盘为准：只读磁盘内容和换行风格，不读取未保存的编辑器模型。打开中的标签如果有未保存修改，结果和它们无关；点击结果时由前端保护现有内容，见下文。

### 流式结果与上限

`parts` 依次收到 `type` 为 `line` 和 `done` 的值；方法返回时 Channel 关闭。

| `type` | 内容 |
|---|---|
| `line` | 一个匹配行：`path`（相对根目录、`/` 分隔）、`line`（从 1 开始）、`text`（有界的行片段）、`prefixTruncated` / `suffixTruncated`、`matches`。同一行上的所有匹配都在同一个 `line` 里。 |
| `done` | 成功的最终汇总：`fileCount`、`matchCount`（匹配处数，不是行数）和 `truncated`。失败时不会发送 `done`。 |

- Go 按文件扫描并把匹配行发送给页面，不先收集工作区里的全部文件；页面随到随显示。
- 单次最多发送 1000 处匹配，与界面显示上限一致。达到上限后 Go 只继续确认是否还有下一处：恰好 1000 处时 `truncated` 为 `false`，确实还有匹配时停止并发送 `truncated: true`，不再发送第 1001 处。
- 读取按文件进行，不缓存所有文件内容。超出上限或取消后不再继续扫描。
- 文件在扫描期间消失时跳过该文件；读取或目录遍历真失败时方法返回错误。已经流出的行仍可能已经显示，但界面必须把这次搜索标为失败，不能当作成功或完整结果。

### 位置协议

Go 在进程内把磁盘字节解码为 UTF-8 字符串并把 CRLF、单独的 CR 统一成 `\n`，再用 RE2 匹配。发给页面的位置不是磁盘字节偏移，而是**归一化文档中的 UTF-16 码元偏移**，与 CodeMirror 使用的坐标一致。

| 字段 | 含义 |
|---|---|
| `start` / `end` | 整个匹配在归一化文档中的 UTF-16 范围，可跨行。 |
| `length` | 整个匹配的 UTF-16 长度；`end - start` 与它相同。 |
| `text` | 匹配文字的前缀，最多 200 个 UTF-16 码元，只用于点击时校验。 |
| `highlightStart` / `highlightEnd` | 该匹配在 `line.text` 片段中的 UTF-16 范围；不在片段内时为 `-1`。 |

- `line.text` 最多约 400 个 UTF-16 码元，边界对齐到完整字符。超长行保留首个匹配附近的窗口，`prefixTruncated` / `suffixTruncated` 表示两侧被截断；同一行后续匹配如果落在窗口外，仍计入处数但没有可见高亮。
- 匹配跨行时归到起始行；行片段只显示起始行，高亮在行尾截断，但 `start` / `end` 仍覆盖完整匹配。
- 返回的行号按归一化后的 `\n` 计算。中文、emoji 和 CRLF 都使用同一套 UTF-16 换算，页面不能把 Go 的字节索引直接交给编辑器。

### 取消、代际与点击过期

- 页面关闭 Channel 时，MyGo 取消这次调用的 context，Go 在读取、匹配和发送之间检查它并尽快结束；不发送 `done`。工作区切换或关闭时 Go 还比较根目录与 `generation`，旧扫描不会把结果交给新根目录。前端在查询、大小写或正则改变时先关闭旧 Channel，并用本次查询的会话身份丢弃迟到的行、汇总和错误。
- 点击结果时，前端先确认结果所属 `generation` 仍是当前工作区，再走现有的打开或切换标签流程。已打开的标签直接切换，不重新读盘，也不覆盖未保存内容。
- 结果带着扫描时的偏移和匹配文字，是磁盘快照。选中前先检查原偏移处的 `text` 仍是同一段匹配；文档在其他位置移动过时，只在该结果行内按匹配文字重新定位。偏移和行内重新定位都失败时显示“搜索结果已过期，请重新搜索”，不盲用旧偏移。零宽匹配没有可校验的文字，行内容变化时同样按过期处理。
- 选区仍是页面自己的编辑器位置；打开、外部修改、删除和保存继续遵守[保存](#保存)与标签页的既有守卫。搜索不绕过“载入磁盘版本”、外部修改/删除状态或 `generation` 检查。

### 当前边界

- P0 只搜索一个根目录，结果按文件和匹配行分组，界面不显示根目录这一级。多根目录搜索见[待办](ui.md#待办)。
- 搜索不实现全文替换、SQLite/FTS 索引、索引缓存服务或设置页范围选择。
- 搜索用的是扫描时的磁盘快照；扫描后磁盘再次变化时，点击可能提示过期。搜索不会声称包含未保存的编辑器内容。

## 文件监听

`Workspace.Watch(generation)` 通过 MyGo 的 Channel 流式返回工作区变化；底层是 `mygo.WatchFiles`，与 MyGo 的 `watch` 插件使用同一个引擎。这里没有使用 `watch.New`：插件把事件直接交给页面，没有过滤点，而 Nicole 必须过滤自己的写入。前端通过 `src/services/watch.ts` 订阅，先收到一次 `ready`，之后每批事件包含 `op`（`create`、`write`、`remove`、`rename`）、相对路径、`oldPath` 和 `isDir`。

| 项目 | 规则 |
|---|---|
| 范围 | 递归监听工作区根。隐藏目录（名字以 `.` 开头）和 `node_modules` 不监听，里面的变化在下次展开时由 `ListDirectory` 重新读取。 |
| 文件类型 | **上报所有非忽略文件，不限于 `.md`**。文件树需要图片、PDF 等文件的新增、删除和改名；非 `.md` 文件的内容写入也上报。 |
| 隐藏文件 | 名字以 `.` 开头的文件照常监听，例如 `.draft.md`；`.DS_Store`、`Thumbs.db`、`desktop.ini` 不监听，因为文件树不显示。 |
| 临时文件 | 名字匹配 `.nicole-<16 位十六进制>.tmp` 的文件不监听。 |
| 代际 | `Watch` 开始时要求 `generation` 与当前工作区一致；工作区切换后，旧 watcher 在下一批事件前结束，不能把旧根的变化交给新页面。没有打开的根目录时直接返回“没有打开工作区”。 |
| 页面关闭 | Channel 关闭或调用方取消时，watcher 结束；页面换文件夹或关闭工作区时先关闭旧 watcher，再开始新的。 |

### 忽略 Nicole 自己的写入

`WriteFile` 和 `CreateFile` 在替换或创建文件前记录该路径和写入内容的 SHA-256，记录保留 5 秒。收到 `write` 或 `create` 事件时，如果路径有记录、未过期，且磁盘内容仍与写入内容完全一致，就丢弃这个事件；其他事件、目录事件和已过期记录照常上报。

- 判定规则基于内容而不是时间：另一个程序在 5 秒内写入不同内容时，哈希不同，事件会上报，不会被误判为 Nicole 自己的写入。
- 另一个程序写入完全相同的内容时，哈希相同，事件会被忽略；从文件内容无法区分来源，这是该规则的已知边界。
- 写入失败时记录立即删除；`remove`、`rename` 和 `hint` 不受此规则影响，删除和移动仍会通知页面。
- 记录只存在内存中，按工作区路径保存；切换文件夹后旧记录不影响新工作区。
- PR4 的图片写入不经过 `writes.record`，所以会按外部写入产生 `create` 事件；文件树需要显示新图片，这是预期行为。
