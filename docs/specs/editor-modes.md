# 编辑模式

概要：

- 提供实时预览、沉浸、源码三种模式，共用同一个 CodeMirror 6 内核。
- 三种模式都必须具备相同的写作能力；沉浸模式另有链接编辑、格式快捷键和边界输入规则。不做浮动工具栏，选中文字后的操作见[界面与交互](ui.md#选中文字后的操作)。
- 拼音输入过程中不能重建当前行的渲染，组合结束后再重建（见[中文输入法](#中文输入法)）。
- 正式版按当前元素展开原文，而不是像演示那样整行展开。

## 三种模式

三种模式都必须支持，用户可以随时切换。模式是全局选择，所有标签页共用，不按标签页记忆；选择保存在[设置存储](workspace.md#设置存储)的 `editorMode` 中并在重启后恢复。首次启动、字段缺失或值非法时使用实时预览；用户切换后写回设置，写入失败仍保留本次选择。

| 模式 | 效果 |
|---|---|
| 实时预览（默认） | 光标所在的地方显示 Markdown 原文，其他地方渲染。类似 Obsidian 的 Live Preview。 |
| 沉浸 | 符号永远隐藏，类似 Typora；光标自动跳过隐藏的符号（atomic ranges）。 |
| 源码 | 一直显示原文。 |

## 单一编辑器内核

只用一个编辑器内核，三种模式只是显示方式不同，通过 CodeMirror 6 的 Compartment 切换。

**不要**另外引入 ProseMirror 那类所见即所得引擎：它保存时要把富文本转回 Markdown，会改写源码；而且每个功能都得做两遍。这与[源码保持干净](product.md#定位)的约束冲突。

渲染基于语法树和 decorations/widgets，语法解析使用 `@codemirror/lang-markdown` 的 GFM 支持（见[技术选型](../architecture.md#技术选型)）。

## 所有模式共用的能力

以下功能在三种模式下都必须能用：

- Slash 命令（见[Slash 命令](slash-commands.md)）
- 快捷键
- 粘贴图片（见[工作区与文件](workspace.md#图片)）
- 拖入图片（见[工作区与文件](workspace.md#图片)）
- 大纲
- 自动保存（见[工作区与文件](workspace.md#保存)）
- 选中文字后输入 `*`、`` ` ``、`~`、`[` 时包裹选区，条件见[界面与交互](ui.md#选中文字后的操作)
- 用 ⌘K 打开链接弹框编辑链接（见[界面与交互](ui.md#链接与图片弹框)）

## 沉浸模式的额外工作

沉浸模式隐藏了所有标记，因此需要额外处理：

- 点击链接或图片时显示弹框，用来编辑看不到的 URL 和路径（见[界面与交互](ui.md#链接与图片弹框)）。
- 格式快捷键用于切换格式（如 ⌘B 切换加粗）。
- 边界输入规则，例如在加粗文字末尾继续输入时，新输入的字是否算加粗。
- 行首边界：隐藏的标题、引用、列表和任务标记不能成为空选区的落点。←、⌘←、Home 和点击最多把光标停在第一个可见字之前；在第一个可见字前按 ← 到上一行末尾，文档第一行时停在原处；⌥←、⌃←、Windows/Linux 的 Ctrl/Alt+←、⌃B 和多光标移动从边界继续向左。Shift 扩展选区保持原有行为。在隐藏标记之后输入文字时标记保持完整。有序列表的序号是可见文字，光标可以进入并停在序号之前。

## 行首边界与 Enter、Backspace

沉浸模式只把真正隐藏或被 widget 替换的行首标记当作结构边界；有序列表的 `1.` 是可见文字，光标可以停在序号之前并编辑序号。

**块第一行规则（仅沉浸模式）**：只有语法树中最外层块的第一行触发特殊处理，后续行保持修复前的 Markdown 行为。第一行第一个可见字前（标题、引用、无序列表为隐藏标记后的第一个字；有序列表为序号前）按 Enter/⇧Enter/⌃O 时，在块上方插入一个空的普通行，块本身完全不变，光标留在原来的文字前；文档第一行也一样。第一行块内容起点（有序列表为可见序号之后）按 Backspace/⌃H 时删除整段行首标记。图片落在第一行行首标记内（包括内容起点）时插到块上方。每次 Enter 是独立的撤销步，视口底部会滚动到光标；⌃O 只在 macOS 处理，Windows/Linux 的 Ctrl+O 仍是打开文件夹。

多行引用/列表的后续行不应用上述规则：Enter 保持 Markdown 续行行为，例如 `> 甲` 的下一行 `> |乙` 生成 `> 甲\n>\n> 乙`，`- 甲` 的下一行 `- |乙` 生成 `- 甲\n-\n- 乙`；Backspace/⌃H 回到基线；图片在续行标记上插到标记后，不拆开列表或引用。这是本 PR 有意与基线不同的行为：`1. 甲\n|2. 乙` 的图片落在 `2. ![](a.png)乙`，`1. 甲\n1|2. 乙` 落在 `12. ![](a.png)乙`，从行左拖到 `- 甲\n- 乙` 第二行落在 `- ![](a.png)乙`。嵌套在已有引用/列表中的新子块如果外层块已从上一行开始，也按续行处理。标题只有一行，不受影响。`1.` 与文字之间（如 `1. |文本`）不属于第一行第一个可见字前（有序列表为序号前），仍按 Markdown 规则拆成 `1.` 和 `2. 文本`。实测结果如下（WKWebView 构建产物，真实 NSEvent；真实输入法由发布前手测确认）：

| 原行 | Enter 后 | Backspace 后 |
|---|---|---|
| `# 标题文本` | 空白行 + 原样 `# 标题文本`，光标在 `标` 前 | 删除 `# `，变成 `标题文本` |
| `> 引用文本` | 空白行 + 原样 `> 引用文本`，光标在 `引` 前 | 删除 `> `，变成 `引用文本` |
| `- 无序列文本` | 空白行 + 原样 `- 无序列文本`，光标在 `无` 前 | 删除 `- `，变成 `无序列文本` |
| `1. 有序文本` | 空白行 + 原样 `1. 有序文本`，光标在 `1` 前 | 从序号前按 Backspace 与基线相同（合并上一行）；序号内部按 Backspace 删除字符 |
| `- [ ] 任务文本` | 空白行 + 原样 `- [ ] 任务文本`，光标在 `任` 前 | 删除 `- [ ] `，变成 `任务文本` |

Backspace/⌃H 在块第一行内容起点按上面的规则删除整段行首标记（包括标题、引用、列表和有序列表的可见序号；例如 `> - 甲` 变成 `甲`）；第一行空块的 ⌃H 走 `deleteMarkupBackward`，其他位置交回默认链，因此成对括号和引号仍由 CodeMirror 的默认命令成对删除。有序任务项（如 `1. [ ] 甲`）的整个行首标记也作为一个单位删除。⌥⌫ 在边界处与基线相同，与上一行合并；文档第一行保持不动。

## 中文输入法

中文输入法在 macOS WKWebView 里的表现是项目的最大技术风险（见[主要风险](../architecture.md#主要风险)）。约束是：**拼音输入过程中不能重建当前行的渲染**。这会直接影响实时预览和沉浸模式隐藏符号的逻辑。

组合状态同时决定自动保存的时机：组合期间不写盘，组合结束后重新计时。保存行为只在[工作区与文件](workspace.md#输入法组合期间)定义，本节只讨论渲染。

实时预览和沉浸模式共用 `src/editor/index.ts` 中的 `preview()`，实现方式：

- 组合输入期间（`view.compositionStarted` 为真）跳过 decorations 重建，只用 `DecorationSet.map` 把已有 decorations 随事务移到新位置，语法树不再重新遍历。
- `composing` 要到第一次组合文本变化时才为真；`compositionStarted` 还覆盖了从 `compositionstart` 到第一次变化之间的更新，在这段时间里重建同样会让 WKWebView 丢掉候选框。
- 跳过重建时记下“渲染已过期”，组合结束后的第一次更新重新构建 decorations。这样即使那次更新只有空事务（例如用 Backspace 撤销整个组合，文档回到原样）也会重新渲染。
- 映射而不是直接保留原位置，是因为组合期间文档仍在变化；映射后 widget 和 decorations 的位置始终有效，但不会重新判断当前行、隐藏符号或任务框。

### 手测清单

真实中文输入法的手感只能在 WebView 里手测，自动化测试覆盖不到。macOS（WKWebView）按下面逐项确认；Windows WebView2 和 Linux（WebKitGTK）待实测。

| 场景 | 操作 | 期望 |
|---|---|---|
| 标题行 | 光标在标题行，在标题文字中间输入拼音 | 组合期间 `#` 的显示状态、标题字号和行高都不变，候选框不消失 |
| 加粗内部 | 光标在 `**加粗**` 中间输入拼音 | `**` 在实时预览和沉浸模式下保持原来的显示状态，粗体不闪烁；上屏的文字仍是加粗 |
| 列表项 | 光标在 `- 项目` 中输入拼音 | 列表符号不重建、不闪烁 |
| 任务项 | 光标在 `- [ ] 任务` 中输入拼音 | 任务框 DOM 不重建，勾选状态不变，任务文字正常更新 |
| 沉浸模式隐藏符号的边界 | 光标停在隐藏的 `#`、`**` 或列表符号边界处输入拼音 | 符号保持隐藏，光标不跳进隐藏区域；组合结束后按新位置重新隐藏 |
| 切换候选词 | 组合期间用数字键、方向键或翻页键切换候选 | 候选框不消失，行内容和光标位置不跳动 |
| Backspace 撤销组合 | 组合期间连续按 Backspace 删除拼音 | 文字逐步还原，候选框不消失；组合结束、文档回到原样后当前行渲染正确 |
| 组合期间停顿 | 输入拼音后停顿超过 1 秒 | 磁盘上的文件不变；状态栏显示见[界面与交互](ui.md#保存状态)，恢复保存的规则见[工作区与文件](workspace.md#输入法组合期间) |
| Esc 取消组合 | 组合期间按 Esc | 拼音消失，文档回到原样，当前行渲染正确；之后再输入或移动光标，渲染仍然正确 |
| 组合期间切换窗口或失焦 | 组合期间点击其他窗口或让编辑器失焦 | 组合结束后当前行渲染能恢复，重新聚焦后继续输入正常 |
| 组合结束后的渲染 | 候选词上屏 | 当前行按最新语法重新渲染：标题、加粗、列表、任务框和隐藏符号都正确 |
| 切标签/重启后不点击 | 切到别的标签再切回，或重启恢复；不点击，直接按 Enter/⇧Enter 或放图片，再打字 | 格式不被破坏，光标留在原文字前 |

## 渲染粒度

演示实现是**整行展开**：光标在某一行时，这一行全部显示原文。正式版应细到**只展开光标所在的那个元素**，例如光标在加粗文本里时只露出这对 `**`，而不是让整行的语法标记都出现。

## 代码块背景

围栏代码块和缩进代码块在实时预览、沉浸、源码三种模式下都画成一整块背景：

- 背景跨过正文列但左右各留 16px 外边距；代码文字仍与正文起点对齐，文字到背景边缘为 16px。首行和末行有圆角，块内各行之间没有缝隙，空行也在背景内。
- 代码块内整行使用 `--reading-font-mono`，围栏、语言标识和缩进代码的空格也使用等宽字体；行高随字体度量略有变化，不影响行首规则、光标定位或背景对齐。
- 引用内的代码块背景左边缘从引用竖线右侧开始，右边缘与其他代码块一致；列表里的代码块保持整列背景。
- 选区层按同样的 16px 范围裁剪，正文和代码块里的选区都不会超出正文列的左右边界；光标不被裁剪。引用内代码块的背景左缘比选区左缘更靠右，选区仍按正文列裁剪。
- 行内代码仍是贴着文字的小块背景，不随代码块规则变化；代码块内的搜索匹配、选中词匹配和括号匹配保留自己的高亮背景。
- 背景画在正文内容下面的独立层，位于 CodeMirror 选区层之下，因此选区、光标和输入法组合文字都不会被背景遮住；Paper 和 Ink 都如此。
- 只为可见范围内的代码行建立装饰。大文档刚打开、语法树还没解析到可见区域时，先不画背景；解析推进后补上，不改变行高或布局，避免背景跳动或错位。
- 背景色使用 `--reading-code-bg`，外侧圆角使用 `--radius-control`，不写死颜色。

## 当前实现

`src/editor/index.ts` 已从交接附件中的 `main.ts`（2026-10 验证，不纳入仓库）移植，接口见[架构](../architecture.md#依赖边界)。当前仍保持演示的**整行展开**，后续再细到元素。

- `preview(reveal)` 生成一个 `ViewPlugin`；文档、视口、选区或语法树变化时，在可见范围内重建 decorations。首次解析只按时间预算解析到文档的一部分；后台解析推进后，新进入语法树的标题、任务框和隐藏标记会自动补上，不需要选区或文档更新。组合输入期间跳过重建，只做位置映射，见[中文输入法](#中文输入法)。
- 遍历语法树：隐藏 `HeaderMark`、`EmphasisMark`、`CodeMark`、`StrikethroughMark`、`QuoteMark`、任务项的列表符号和链接的 URL；把列表符号、任务框、图片、分割线替换成 widget；标题和引用用行级 decoration。
- 代码块背景由独立 layer 绘制，规则见[代码块背景](#代码块背景)。
- 任务框自绘：`appearance: none` 的 `<input type="checkbox">` 覆盖在容器上，负责点击和键盘操作；外框、背景和勾选标记都由容器上的 CSS 绘制，读取 `--nicole-checkbox-*` 变量，回退见 `src/editor/index.ts` 的 `editorTheme`，因此亮暗切换不需要重建编辑器。任务框 widget 的 `eq` 只比较勾选状态，`updateDOM` 原地更新勾选样式以保留焦点；点击时用 `view.posAtDOM` 和文档内容取当前位置与状态，避免在前面输入文字时重建任务框。
- 任务框聚焦时，裸空格切换勾选；任一修饰键加空格（⌃、⇧、⌥、⌘）属于编辑或系统快捷键，不会切换勾选。Tab / ⌥Tab 移动焦点。主修饰键加 F/G/A 和 ⇧G（macOS 为 ⌘，Windows/Linux 为 ⌃）先交回编辑器焦点再执行查找、查找下一个、查找上一个和全选；其他编辑键、输入法组合和提交、paste/cut 及原生编辑动作不能落到正文，焦点也不被抢回正文。
- 任务框获得焦点时清除 WebKit 可能留在正文 contentEditable 里的原生选区，这是挡住不可取消的输入法提交的关键；CodeMirror 的选区仍保存在编辑器状态中。焦点回到正文时先调用 `view.focus()` 恢复 CodeMirror 的选区，避免 WebKit 在清空后的 contentEditable 起点写入光标并把长文档滚回顶部。原生 Select All 菜单动作在 `selectstart` 落在页面背景时显式执行编辑器的全选，不再依赖这段被清空的原生选区；焦点不在任务框时不会拦截 `selectstart`。
- 聚焦的任务框被 `replaceDocument`、撤销或虚拟化移除、WebKit 把焦点直接丢到 BODY 时，编辑器在文档或视口更新、任务框失焦后的定时器、窗口重新获得焦点三处检查并交还焦点。焦点已转到其他控件、窗口仍失焦或编辑器已销毁时不抢焦点；窗口失焦期间移除的任务框会等到窗口重新激活后再恢复。点击任务框不抢焦点，光标留在原处，之后的按键再进入正文。
- 沉浸模式额外注册 `EditorView.atomicRanges`，让光标跳过隐藏的符号；行首的隐藏标记另由选择守卫修正，守卫只移动空选区并处理边界移动，不改动 decorations，因此组合输入期间不会重建渲染。有序列表的 `1.` 仍按原文显示（`buildDecorations` 只把 `-*+` 换成圆点 widget），并且不跳过，光标可以停在序号前编辑序号。
- 用 ⌘B（CodeMirror 的 `Mod-b`）切换加粗；光标折叠时插入一对空标记，选中文本时在两侧加 `**`。
- 图片 widget 只在 `resolveImage` 返回地址时替换原文，否则保留 Markdown；应用层按当前文件和 generation 生成协议地址（见[工作区与文件](workspace.md#图片)）。
- 编辑区拦截含图片的粘贴和含文件的拖放。粘贴时通过 `onPasteImage` 交出插入凭据；拖放路径和坐标来自 MyGo 事件，应用层先用 `containsPoint(x, y)` 确认落点在编辑区内，再用同一坐标调用 `createInsertionTicket`。`insertImages(ticket, markdown)` 在一个事务里插入，因此是一个撤销步；编辑器持续映射凭据位置，组合输入期间排队，组合结束后逐条插入。非空行开头单独占一行（三种模式一致）。沉浸模式第一行按上面的块第一行规则插到块上方；续行和实时预览/源码模式保持基线，图片插在标记后或在光标处。空块在标记后的内容位置插入。
- 三种模式的扩展通过同一个 Compartment 切换，`EditorView` 不重建。
- 编辑器主题只读 CSS 变量，亮暗切换只改 class（见[主题与字体](theming.md#编辑器主题)）。

尚未实现：展开粒度细化到元素、链接/图片弹出编辑、slash 命令、选区包裹和边界输入规则。
